# CampusTrace

**Проверяемый визуальный профиль университета.** Вводите название вуза — получаете фотографии кампуса, общежитий, аудиторий, библиотек, спортивных объектов, лабораторий и студенческой жизни, где у **каждого** кадра есть кликабельный первоисточник, лицензия, автор, даты и явно названное основание, почему он связан именно с этим вузом. Там, где материалов нет, сервис так и говорит — и отдельно различает «проверено, ничего не нашлось» и «источник не ответил, проверить не успели».

> Кейс: **LOCUS Startup Hackathon 2026, Кейс 01 «Визуальный профиль университета»**.

## 1. Задача и решение

**Проблема.** Абитуриент выбирает вуз по картинке, а картинки в интернете — чужие, стоковые, устаревшие или вовсе с другого кампуса. Поиск по картинкам не говорит, кто автор, можно ли это показывать и снято ли это вообще здесь.

**Наше решение — не «ещё одна галерея», а проверяемый паспорт.** Ключевая идея: **разделять находку и доказательство**. CampusTrace никогда не утверждает больше, чем может показать:

| Что мы говорим | Что за этим стоит |
|---|---|
| «Вероятно» | Файл найден в тематическом источнике вуза, лицензия есть, но конкретный корпус не доказан |
| «Городской контекст» | Это кадр города, и мы прямо говорим, что это **не** кампус |
| «Требует проверки» | Источник и лицензия есть, но что изображено — не удалось определить ни по тексту, ни по изображению |
| «Не проверено: источник был недоступен» | Раздел пуст **не потому**, что материалов нет, а потому что источник упал на середине |

Слова «подтверждено» в значении «доказано место съёмки» в интерфейсе нет вообще — потому что доказать это по открытым данным мы не можем, а притворяться нельзя.

**Три вещи, которых обычно нет у аналогов:**

1. **Доказательства вместо «уверенности».** У каждого кадра есть список независимых подтверждений: здание вуза в Wikidata с типом (библиотека, общежитие, стадион), отметка «на фото изображено» (depicts) в структурированных данных Commons, категория Commons, название вуза в файле, геотег рядом с точкой кампуса, визуальная проверка изображения. Карточка показывает **уровень достоверности** (высокая — 3 и более вида подтверждений, средняя — 2, низкая — 1 или 0; понижается при расхождении проверок и неопределённой категории), число подтверждений и каждое из них ссылкой — а не выдуманный процент.
2. **«Откуда мы это знаем» — лента источников.** Под названием вуза медленно движется строка логотипов (Wikipedia, Commons, Wikidata, Reddit, YouTube, Instagram, 2ГИС…) — только тех, где для этого вуза реально что-то нашлось, с числом находок. Клик открывает всё, что пришло из этого источника: фото, обсуждения, факты, новости.
3. **«Спросите о вузе».** Вопрос обычными словами («есть ли общежитие?») — ответ собирается только из пронумерованных источников этого профиля (реестр, Wikidata, Википедия, фото, обсуждения) с номерами ссылок. Ответ без действительной ссылки заменяется на «в собранных источниках ответа нет». Модель не спрашивают, что она сама знает о вузе.
4. **Независимая визуальная проверка.** Категория Commons и подпись к файлу часто написаны одним человеком — это один источник, а не два. Vision-модель (Groq `qwen/qwen3.8-27b` или xAI Grok) смотрит на **пиксели** и называет тип места. При расхождении слоёв статус **понижается**.
5. **Карта пробелов.** Профиль показывает, каких категорий не хватает, и почему — это готовый запрос вузу «дайте официальные материалы под открытой лицензией».
6. **Воронка отбора видна пользователю.** Кандидатов → прошли лицензию → уникальных после дедупликации → опубликовано. Ничего не происходит «в чёрном ящике».

## 2. Как запустить за 3 минуты

Требуется Python 3.11+ и интернет.

```bash
cd campustrace-mvp
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# ОБЯЗАТЕЛЬНО: в .env замените your-email@example.com на реальный контакт.
# Nominatim и Wikimedia требуют, чтобы клиент себя идентифицировал.
set -a; source .env; set +a

uvicorn app.main:app --host 127.0.0.1 --port 8765
```

Откройте <http://127.0.0.1:8765>. API-документация: `/docs`. Health-check: `/api/health`.

**Все ключи опциональны.** Без единого ключа работает: поиск вуза, сбор фотографий, лицензии, дедупликация, категории по тексту, карта, сравнение. Ключи только добавляют слои:

| Переменная | Что включает | Что будет без неё |
|---|---|---|
| `GROQ_API_KEY` | Визуальную проверку фото (`qwen/qwen3.8-27b`, мозаика 2×2) **и** сводку по отзывам студентов | Категории только по структурированным данным и тексту; профиль **прямо сообщает**, что визуальная проверка не выполнена |
| `GROK_API_KEY` | Альтернативный vision-провайдер (xAI); если задан, используется вместо Groq | — |
| `CEREBRAS_API_KEY` | Запасной текстовый ИИ (бесплатно ~1 млн токенов/сутки): включается, когда у Groq кончился минутный или **суточный** лимит (~200 тыс. токенов на модель) | Когда лимит Groq исчерпан, ИИ-функции честно пишут «дневной лимит исчерпан» |
| `TAVILY_API_KEY` | Быстрый веб-поиск отзывов и статей со сниппетами (бесплатно, без карты) | Поиск идёт через `browser_search` Groq — ~35 тыс. токенов за сессию |
| `MAPBOX_TOKEN` | Второй геокодер + альтернативные изохроны | Карта работает (MapLibre + OpenFreeMap, без ключа); координата помечается «только один источник» |
| `BRAVE_API_KEY` | Поиск обсуждений на форумах и офиц. страниц | Работает только Reddit через PullPush |
| `FLICKR_API_KEY` | Дополнительные фото под CC-лицензиями | Только Wikimedia Commons |
| `REDDIT_CLIENT_ID` + `REDDIT_CLIENT_SECRET` | Официальный Reddit API (бесплатное приложение типа script) для блока «Голоса студентов»; без него используется архив PullPush, который часто отвечает 429 | Меньше обсуждений; блок честно пишет, что найдено недостаточно |
| `OPENROUTESERVICE_API_KEY` | Изохроны пешей доступности | Зона не рисуется (и **не** подменяется кругом) |
| `YOUTUBE_API_KEY` | Видео с проверенного офиц. канала | Блок видео пуст |

Базовая карта — **MapLibre GL + OpenFreeMap, без API-ключа**. Это сознательный выбор: демонстрация не должна падать из-за чужой квоты во время защиты.

## 3. Тестовый сценарий для жюри

Сценарий рассчитан на то, что вы введёте вуз, которого нет в нашем демо-видео.

**Шаг 1. Любой незнакомый вуз.** Введите на главной, например, `Universität Heidelberg`, `Kyoto University` или `МГУ`. Поиск понимает кириллицу, короткие аббревиатуры (`MIT`, `NYU`) и локальные написания. Вуз выбирается вручную — первый результат не подставляется автоматически, потому что одноимённых организаций много.

**Шаг 2. Галерея — первое, что вы увидите.** Фильтры слева переключают 8 разделов кейса + «Требует проверки». Под каждым фото сразу видны автор, лицензия (ссылкой на её условия) и ссылка на источник.

**Шаг 3. Нажмите «Проверить источник» на любом кадре.** Откроется паспорт: категория, статус, откуда найден файл, автор, лицензия, дата загрузки и дата съёмки (это разные даты), SHA-1, перцептивный хеш, вердикт визуального классификатора и — главное — **согласуются ли две независимые проверки**.

**Шаг 4. Проверьте честность пустот.** Прокрутите до «Полнота источников». Ноль в разделе подписан либо «Проверено — материалов не найдено», либо «Не проверено: источник был недоступен». Это разные утверждения, и мы их не смешиваем.

**Шаг 5. Проверьте, что мы не выдаём город за кампус.** Откройте фильтр «Город» — эти кадры имеют статус «Городской контекст» и явную пометку, что связь с кампусом не утверждается.

**Шаг 6. Два вуза одного города.** Соберите `Nazarbayev University`, затем в блоке «Сравнить покрытие» найдите `Astana IT University`. Общая городская фотография корректно принадлежит обоим профилям (составной ключ `(ror_id, asset_id)` в БД). В таблице сравниваются все 8 разделов, и ноль из-за упавшего источника подписан отдельно.

**Шаг 7. Отказ источника.** Нажмите «Обновить данные» несколько раз подряд. Wikimedia ответит `429`; профиль станет `partial`, предыдущая сохранённая версия останется доступной, и сервис скажет, что именно не успел проверить.

## 4. Стек и архитектура

**Backend:** Python 3.11, FastAPI, httpx (async), SQLite, Pillow (перцептивные хеши).
**Frontend:** ванильный JS без фреймворка и сборщика, MapLibre GL JS, COBE (глобус). Никакого npm-бандла — страница отдаётся статикой.
**Хранилище:** SQLite (профили, материалы, кэш источников, журнал событий).

```text
Поиск по названию
  └─ ROR v2 + локальные синонимы/транслитерация  ──> institution_id (ROR ID)
       │  (идентичность: город, страна, алиасы, домен, Wikidata QID)
       ▼
  Сбор кандидатов (параллельно, у каждого адаптера свой таймаут и учёт отказа)
       ├─ Wikidata SPARQL: здания вуза (P361/P137/P127) с фото и типом P31  ← категория по типу
       ├─ Commons depicts: haswbstatement:P180=<вуз|здания>                 ← «на фото изображено»
       ├─ Commons geosearch у точки кампуса (P625) — только вместе с названием вуза/здания
       ├─ Wikimedia Commons: категория вуза + подкатегории (без коллекций/карт/сканов, ≤6 файлов из одной)
       ├─ Commons search: визуальные запросы по названию
       ├─ Wikipedia (en/ru): изображения статьи, если Commons беден
       ├─ Wikidata P18: официальное изображение
       ├─ Flickr: поиск по CC-лицензиям (опционально)
       └─ Отдельно: поиск по городу — это ДРУГОЕ утверждение
       ▼
  Фильтр лицензии  ──> только открытые лицензии (CC0 / CC BY / CC BY-SA / PD / GFDL); остальное отбрасывается и считается
       ▼
  Слой 1: текстовая классификация
       (название + описание + провенанс подкатегории; стоп-слова событий;
        по умолчанию НЕ «кампус», а «unknown»)
       ▼
  Дедупликация: SHA-1 (точные копии) + dhash/Hamming≤5 (визуально похожие)
       ▼
  Слой 2: визуальная классификация (Groq qwen3.8 или xAI Grok; миниатюры 330 px
          уходят base64 мозаикой 2×2 — 4 фото за запрос; при 429 проверка
          останавливается и профиль сообщает, сколько кадров не проверено)
       ├─ «не место» ──────────> кандидат снимается с публикации
       ├─ «город, не кампус» ──> переносится в раздел «Город»
       ├─ совпало с текстом ───> основание добавляется, статус НЕ повышается
       └─ РАСХОЖДЕНИЕ ─────────> статус понижается до «не подтверждено»
       ▼
  evidence[] + evidence_level (число независимых подтверждений) у каждого кадра
       ▼
  Снимок профиля: complete | partial + состояние каждой из 8 категорий
  (параллельно /preview отдаёт первые лицензированные кадры из Wikidata за ~3 с)
       ▼
  SQLite: profiles + assets(ror_id, id) + source_events + research_cache
       ▼
  Одностраничный UI: галерея → описание по источникам → полнота → карта → сравнение
```

**Файлы:**

| Файл | Ответственность |
|---|---|
| `app/main.py` | HTTP API, бюджет времени, объединение одинаковых запросов, кэш |
| `app/pipeline.py` | Сбор кандидатов, текстовая классификация, дедупликация, описание |
| `app/vision.py` | Независимая визуальная классификация и правила согласования слоёв |
| `app/integrations.py` | Адаптеры внешних API: таймаут, кэш, rate limit, учёт отказов |
| `app/atlas.py` | География: перекрёстная проверка координат, границы OSM, изохроны |
| `app/discovery.py` | Поиск и ранжирование организаций, транслитерация, пагинация |
| `app/db.py` | Схема SQLite и миграция |
| `app/voices.py` | Поиск публичных обсуждений + сводка со ссылками |
| `scripts/benchmark.py` | Замер реального времени ожидания на выборке вузов |

**Ключевые архитектурные решения:**

- **Каждый адаптер обязан вернуть**: идентификатор, лицензию, дату, основание связи с вузом, и — при отказе — состояние отказа. Источник, который этого не даёт, не подключается.
- **Отказ не стирает данные**: если обновление упало, показывается предыдущий сохранённый профиль с явной пометкой.
- **Один процесс, один uvicorn worker**: rate limiter Wikimedia и объединение одновременных запросов работают в пределах процесса.

## 5. Как принимается решение по каждому кадру

1. **Идентичность.** ROR ID — стабильный идентификатор организации. Пользователь выбирает вуз сам, из списка с городом и страной.
2. **Лицензия — жёсткий фильтр.** Файл без явно указанной лицензии не попадает в галерею ни при каких условиях.
3. **Текстовый слой.** Название файла, описание и провенанс подкатегории. Здесь исправлен главный дефект: раньше `campus` был **категорией по умолчанию**, поэтому наградные знаки, концерт, заседание сената и выпускной попадали в «кампус». Теперь по умолчанию — `unknown`, а список стоп-слов событий (en/ru/et/kk) запрещает общую догадку «кампус» для кадра, в названии которого описано событие, а не место.
4. **Дедупликация.** SHA-1 ловит точные копии, dhash по миниатюре — визуально похожие (Hamming ≤ 5). Раньше хеширование молча не выполнялось вообще (миниатюры Commons отдаются с `thumb.wikimedia.org`, а проверка хоста этого не знала), и `0 дублей` означало «не проверяли». Теперь пользователю показывается, сколько кандидатов реально захешировано.
5. **Визуальный слой.** Grok vision получает только те кадры, что уже прошли фильтр лицензии, — квота не тратится на то, что мы всё равно не опубликуем. Ответ модели ограничен фиксированным словарём сцен; свободный текст модели игнорируется. Результат кэшируется по `asset_id`.
6. **Согласование.** Если слои расходятся — статус понижается. Модель с низкой уверенностью **не может** быть единственным основанием ни опубликовать, ни удалить кадр.
7. **Описание кампуса** (требование 7 кейса) собирается **только** из найденного: какие объекты имеют лицензированное фото, за какие годы, сколько кадров с геотегами, чего не нашли и чего не успели проверить. Маркетинговая генерация без источников отсутствует как класс.

## 6. Источники, API и AI — полный список

### Обязательные (работают без ключа)

| Источник | Назначение | Лицензия/условия |
|---|---|---|
| [ROR API v2](https://ror.readme.io/docs/rest-api) | Идентичность организации, алиасы, город, домен | CC0, без ключа |
| [Wikidata](https://www.wikidata.org/) | Commons-категория `P373`, координата `P625`, студенты `P2196`, канал `P2397`, изображения `P18/P8517/P3451/P5775` | CC0, без ключа |
| [Wikidata Query Service](https://query.wikidata.org/) | SPARQL: здания и объекты вуза с фото и типом `P31` | CC0, без ключа |
| [Wikimedia Commons](https://commons.wikimedia.org/) | Файлы, метаданные прав, структурированные данные `depicts` (P180), геопоиск | Лицензия у каждого файла своя; требуется корректный User-Agent |
| [Openverse API](https://api.openverse.org/) | Открытые фото (в основном Flickr) с автором и ссылкой на первоисточник; берутся только лицензии CC BY, CC BY-SA, CC0, PDM; название вуза обязано быть в названии или тегах, категория — только из названия | Без ключа: 20 запросов/мин и 200/сутки; ответы кэшируются на 24 ч |

### AI-компоненты

**Лимит vision честно ограничен.** Бесплатный Groq даёт ~7000 входных токенов в минуту, а одно изображение стоит ~1600–1800 токенов независимо от размера. **Ни одна модель не генерирует изображения, не описывает кампус «своими словами» и не выставляет оценок вузу.**

## 8. Производительность: как мы её измеряем

Жюри оценивает **полное** время: от ввода названия до полезного результата, лимит 30 секунд. Поэтому:

- Замер начинается **до** запроса в ROR (раньше поиск организации был вне измерения — и цифра получалась красивее реальности).
- Серверный бюджет — `PROFILE_BUDGET_SECONDS` (по умолчанию 24 с) плюс 3 с страховочного таймаута; остальное оставлено на поиск, передачу и отрисовку.
- Первые кадры приходят отдельно через `/api/profiles/{id}/preview` (изображения Wikidata вуза и его зданий, один запрос к Commons) и показываются прямо на экране загрузки.
- Бюджет проверяется **на каждой дорогой стадии**: пагинация Commons, дополнительные поисковые запросы и визуальная классификация пропускаются, если времени не осталось, и профиль честно помечается неполным.
- В ответе есть `timings` (по стадиям), `elapsed_ms` и `time_to_first_asset_ms`.

## 9. Продуктовое решение по Instagram/Threads

Соблазн очевиден: в Instagram и Threads больше «живых» фото кампуса, чем в Wikimedia Commons. Мы **сознательно не берём оттуда фотографии**, и вот почему:

1. У Instagram и Threads **нет публичного API** для такого поиска, а у контента **нет открытой лицензии** на переиздание.
2. Правила кейса прямо запрещают «выдавать стоковые или чужие фотографии за конкретный кампус». Встроить чужой снимок из соцсети в галерею «фото кампуса» — ровно это и есть.
3. Нарушение лицензий источников — отдельный пункт запретов кейса.

**Что мы делаем вместо этого.** Публичные обсуждения (Reddit, студенческие форумы, студенческие издания) используются как **текстовое свидетельство**: заголовок, короткая цитата, ссылка на первоисточник и нейтральная сводка. Фотографии оттуда **не встраиваются**. Для изображений источники остаются лицензионно чистыми: Wikimedia Commons и Flickr с фильтром по CC-лицензиям.

Это сознательный размен recall на правовую чистоту. Если вуз захочет более богатую галерею — «карта пробелов» в профиле показывает, каких именно материалов не хватает, и вуз может передать их под открытой лицензией.

## 12. Тесты

```bash
python3 -m unittest discover -s tests -v   # 88 тестов
python3 -m compileall -q app
node --check static/app.js
```

Тесты закрывают именно те свойства, которые легко потерять при доработке:

- городской кадр никогда не публикуется как кампус;
- файл без лицензии не публикуется;
- перцептивный хеш действительно считается для `thumb.wikimedia.org` (регрессия на реальный дефект);
- визуально близкие кадры схлопываются;
- слова о событии не дают категорию «кампус»;
- расхождение двух слоёв **понижает** статус, а не переписывает категорию;
- неуверенная модель не может в одиночку удалить кадр;
- модель, ответившая вне словаря, игнорируется;
- пагинация Commons реально ходит по `cmcontinue`;
- короткая аббревиатура (`MIT`) находится, но не срабатывает внутри слова `Summit`;
- описание кампуса не выдумывает объектов и разделяет «пусто» и «источник упал»;
- геокодеры, расходящиеся на десятки километров, не дают «подтверждённую» точку;
- изохрона не рисуется без ключа маршрутизации;
- отказ источника не стирает сохранённый профиль;
- блок «Голоса студентов» **никогда** не возвращает встраиваемое изображение — правовая политика проверяется тестом, а не обещанием в README;
- тип здания из Wikidata задаёт категорию; факультет или спутник не считаются местом;
- проходят только открытые лицензии (в том числе для структурированных источников);
- геотег сам по себе не делает кадр «кампусом»;
- сканы карт и коллекции библиотеки не попадают в «библиотеку» (регрессия Kyoto);
- портреты и визиты не считаются видом кампуса;
- несогласная визуальная проверка не засчитывается как подтверждение;
- мозаика 2×2 разбирается по плиткам независимо, битая плитка — «не проверено», а не догадка.

## 13. Ограничения — честно

- **Мы не доказываем место съёмки.** Категория Commons — свидетельство связи, не геодоказательство. Визуальный классификатор определяет **тип места**, а не адрес. Максимальный статус — «вероятно».
- **Точность не измерена независимыми разметчиками.** Ни один процент точности в этом README не указан, потому что для него нужна ручная разметка двумя проверяющими на выборке вузов. Методика такого замера описана в аудите проекта; сам замер — следующий шаг.
- **Охват ROR не равен списку всех вузов мира** — реестр ориентирован на организации, связанные с исследованиями. Для небольших колледжей результатов может не быть.
- **Полнота зависит от Wikimedia.** У многих вузов в Commons просто нет фотографий общежитий и аудиторий. Пустой раздел у нас — это факт о доступности открытых материалов, а не о вузе.
- **Wikidata `P2196`** (число студентов) может быть без года или без первичного источника; мы показываем год и ссылку и предупреждаем об этом.
- **Публикации OpenAlex** — это не число студентов и не качество обучения.
- **Один процесс.** Для настоящей нагрузки нужны PostgreSQL, общий распределённый rate limiter, очередь и наблюдаемость.
- **OSM-слои построены вручную** для трёх вузов (NU, UPenn, AITU). Для остальных карта показывает точку с указанием её точности и происхождения.

## 14. Чек-лист правил кейса

| Запрещено кейсом | Как это исключено у нас |
|---|---|
| Выдавать стоковые/чужие фото за конкретный кампус | Кадр без лицензии не публикуется; городские кадры имеют отдельный статус и прямую пометку; фото из соцсетей не встраиваются вообще |
| Скрывать ручной подбор под видом автопоиска | Ручных подборок фото нет. Единственные ручные данные — OSM-слои трёх вузов и локальные синонимы поиска; и то и другое описано выше |
| Подделывать источники, скорость, достоверность | Клик по любому фото открывает первоисточник; таблица скорости — живой замер с датой, стендом и долей ответов из кэша; «показатель достоверности» — не процент, а уровень (высокая / средняя / низкая), вычисляемый по числу независимых видов подтверждений; понижается при расхождении текста и изображения, неопределённой категории и городском контексте, никогда не повышается; каждое подтверждение раскрывается ссылкой |
| Нарушать лицензии источников | Жёсткий фильтр лицензии; атрибуция на карточке и в паспорте; соблюдение лимита Nominatim и требований User-Agent; ODbL-атрибуция карт |
| Публиковать секретные ключи | `.env` в `.gitignore`; все ключи только через переменные окружения; в коде нет ни одного литерала ключа |

| Требование кейса | Состояние |
|---|---|
| 1. Поиск по названию + разрешение неоднозначности | Есть: ROR + локальные синонимы, транслитерация, пагинация, выбор вручную |
| 2. Кампус, общежитие, аудитории, библиотека, город | Есть; полнота ограничена доступностью открытых материалов, пробелы показаны явно |
| 3. Автоматическая классификация | Есть: **два независимых слоя** — текстовый и визуальный |
| 4. Удаление одинаковых, похожих и нерелевантных | Есть: SHA-1 + dhash + снятие нерелевантных визуальным классификатором |
| 5. Проверка связи фото с вузом/объектом/городом | Есть на уровне оснований и статусов; геодоказательства не заявляются |
| 6. Кликабельный источник и дата | Есть: источник, автор, лицензия, дата загрузки и дата съёмки раздельно |
| 7. Краткое описание кампуса из источников | Есть: собирается только из найденных объектов, со ссылками |
| 8. Фильтры общежитие/спорт/лаборатории/студенческая жизнь | Есть, плюс отдельный раздел «Требует проверки» |

## 15. Что записать в демо-видео

Ограничение — **3 минуты**. Сценарий (показывать экран, говорить коротко):

| Время | Что показать | Что сказать |
|---|---|---|
| 0:00–0:20 | Главная, глобус | «Абитуриент выбирает вуз по картинкам, но не знает, чьи это картинки и тот ли это кампус. CampusTrace показывает только то, что может подтвердить источником» |
| 0:20–0:50 | Ввод **незнакомого** вуза, сборка профиля | «Поиск понимает кириллицу и аббревиатуры. Организация выбирается вручную — одноимённых много. Полная сборка укладывается в бюджет 30 секунд» |
| 0:50–1:25 | Галерея, фильтры, карточка с автором и лицензией | «Восемь разделов кейса. Автор и лицензия — сразу под кадром, а не спрятаны» |
| 1:25–2:00 | «Проверить источник» → паспорт | «Вот главное: две независимые проверки — текст источника и визуальный классификатор. Если они расходятся, мы **понижаем** уверенность, а не выбираем удобный вариант» |
| 2:00–2:25 | Полнота источников: пустой раздел и раздел с упавшим источником | «Ноль ноль рознь. "Проверено, не нашли" и "источник не ответил" — разные утверждения, и мы их различаем» |
| 2:25–2:45 | Фильтр «Город» + сравнение двух вузов одного города | «Городской кадр никогда не выдаётся за кампус. Сравниваются все восемь разделов, а ноль из-за отказа источника подписан отдельно» |
| 2:45–3:00 | Финал | «Мы не доказываем место съёмки — по открытым данным это невозможно. Мы показываем, что именно проверено, а что нет. Это и есть продукт» |

**Технически:** экран 1920×1080, запись без звука окружения, голос поверх, показывать реальный развёрнутый сайт (не localhost), не ускорять таймер сборки. **Вуз в видео должен отличаться от того, который вы покажете на защите.**

## Приложение: маршруты API

```text
GET /api/health
GET /api/integrations
GET /api/search/suggest?q=НУ&page=1
GET /api/institutions?q=Nazarbayev%20University
GET /api/profiles/{ror_id}            # ?refresh=true — принудительная пересборка
GET /api/profiles/{ror_id}/preview    # первые лицензированные кадры из Wikidata за ~3 с
GET /api/profiles/{ror_id}/ask?q=...  # ответ только по источникам профиля, с номерами ссылок
GET /api/profiles/{ror_id}/news       # заголовки GDELT, где назван вуз
GET /api/profiles/{ror_id}/extras     # кэшируется на час
GET /api/profiles/{ror_id}/student-voices
GET /api/assets/{asset_id}?ror_id={ror_id}
GET /api/atlas/{ror_id}
GET /api/atlas/{ror_id}/isochrone?mode=walking&minutes=15
GET /api/compare?left={ror_id}&right={ror_id}
```

Полезные поля ответа профиля: `evidence` и `evidence_level` у каждого кадра, `rejected_license_count`, `institution.buildings`, `profile_status`, `category_status`, `unclassified_count`, `vision`, `rejected_by_vision`, `timings`, `time_to_first_asset_ms`, `duplicate_count`, `license_eligible_count`, `warnings`, `source_events`, `from_cache`.
